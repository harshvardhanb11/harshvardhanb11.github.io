A custom domain

An optional personal address pointing to the host. It is separate from the website files and needs renewal if you register one.

The shortest publishing route

Use your own hosting account and upload the already-built folder. There is no compilation step or Git connection required for manual upload.

Upload the prepared site

Use the provider’s manual upload flow to deploy dist. Upload that folder’s website contents, rather than the entire source package.

04

Copy the production address it returns

The provider creates the real public URL. Do not use an example address from a guide or a local file path as your website link.

05

Verify it as a visitor

Open the URL in a signed-out or private window and on your phone. Check the home page, a project’s standalone page, the labs, and the resume. Then use that URL in applications and your GitHub profile.

What about “available forever”?

No provider can guarantee access until infinity. A public address depends on the hosting account, project, and service staying active. Keep this source package so you can move the site if needed. No hosting payment or domain purchase was made during the build.

How do I update the site?

Edit the content or styling, run node build.mjs, and upload the updated dist folder. Use the same hosting project to keep its main public address.

How do I finish social previews and search metadata?

Once you know the real public address, set SITE_URL to that exact HTTPS address when running the build. The README explains the command. Rebuild and redeploy to add canonical links, a sitemap, and absolute social-preview image URLs.

What still needs a real browser check?

The build passed automated logic, DOM interaction, link, and accessibility checks described in the validation report. A full browser rendering and device review could not be completed in the workspace. Review text wrapping, keyboard focus, animation, and the mobile menu on your actual devices before widely sharing the site.
